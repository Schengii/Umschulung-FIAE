## Stolperfallen dieser Umgebung

- **Windows/Bash:** Skripte mit Backslashes oder vielen Anführungszeichen per Write-Tool in eine Datei schreiben und ausführen, nicht als Heredoc (siehe Memory „Bash-Heredoc-Backslash-Falle“). Mehrteilige Befehle mit `;` oder `|` werden gelegentlich abgelehnt; einzeln absetzen.
- **`npm ci` bricht unter Windows ab**, solange ein anderer Prozess (z. B. ein Vitest-Watcher oder MCP-Server) eine `.node`-Datei unter `node_modules` hält, und lässt `node_modules` halb gelöscht zurück. Dann `npm install --no-audit --no-fund` (stellt alles wieder her).
- **`npx playwright install <browser>` mit einer anderen Playwright-Version löscht die Browser der aktuellen Version.** Nach einem Test mit anderer Version `npx playwright install chromium firefox webkit` mit der gepinnten 1.63.0 ausführen.
- **Visuelle Tests:** lokale Läufe erzeugen `*-win32.png` (git-ignoriert); eingecheckt werden nur die Linux-Bilder aus der CI.
- **Subset und Service Worker:** nach jeder Änderung an HTML/CSS/JS `npm run regen`, danach `npm run check`. Neue Projektseiten entstehen mit `npm run generate-data`, ihr Sitemap-Eintrag ist Handarbeit.
- **Flaky:** `daily_question.spec.js` (Test „371 Tage …“, Aktivitätsraster) schlägt gelegentlich fehl, auch auf unverändertem Code.
- Neue `localStorage`-Schlüssel gehören in `constants.js`, die Backup-Allowlist (`progress-backup.js`) und die Liste in `datenschutz.html` (der Test `privacy_storage_keys.test.js` erzwingt das). Heute neu: `flashcards_new_per_day`, `flashcards_new_today`, `exam_history`, `fachgespraech_results`.
